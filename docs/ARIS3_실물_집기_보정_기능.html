ARIS3 실물 집기·보정 기능 (2026-11-13 ~ 11-14)

실물 E0509 + 위쪽 RealSense D455 로 큐브를 집고 쌓기 위해 이틀 동안 더한 기능을 한곳에 정리한다. 각 기능의 코드 위치, 동작 순서, 끄는 방법, 시험, 아직 확인하지 못한 점을 적는다.

실물 지원은 시험 중이다. 시뮬레이션·합성 영상 시험에서 성공했다고 실물에서도 된다는 뜻은 아니다. 비상정지는 항상 손이 닿는 곳에 둔다.

1. 전체 흐름

D455 ──(scripts/aris3_realsense_pub.py)──> 컬러 JPEG 30 Hz · 깊이 PNG 10 Hz · camera_info
   │
   ├─(scripts/aris3_color_detector.py)──> /aris3/vision/detections_px
   │      큐브 색·픽셀·층(깊이)·회전각·집기용 픽셀(원근 보정)
   │
   └─(aris3_real_bridge, 보정 ① 블록 마커)── ArUco 마커 중심·깊이
                                   │
ARIS (aris3_gui_cpp) ── 음성·클릭·손짓 ──> /aris3/real/pick_place, /aris3/real/calibration
                                   │
aris3_real_bridge ── 각도 맞추기(J6) · 중심 맞추기 · 층 높이 ──> E0509 (RobotLink 안전 경로)

2. 카메라: RealSense D455 컬러 + 깊이

항목 내용
파일 scripts/aris3_realsense_pub.py
발행 /aris3/overhead_camera/image/compressed (1280x720 JPEG 30 Hz), /aris3/overhead_camera/depth/compressed (컬러에 맞춘 깊이 mm, 16 bit PNG, 1/2 크기 10 Hz, format 16UC1; png; scale=2), /aris3/overhead_camera/camera_info
실행 ~/venvs/aris3_camera/bin/python scripts/aris3_realsense_pub.py (설치는 실행·테스트 가이드)

깊이를 반으로 줄여 보내는 이유: 원래 크기 16 bit PNG 는 한 장 0.5 MB 를 넘어 Fast DDS 가 UDP 조각으로 나누다 버린다.

3. 색 검출: 층·원근 보정·각도

파일 scripts/aris3_color_detector.py (--show 로 OpenCV 창). 출력 DetectedObject 의 필드:

필드 뜻
pose.position.x, y 큐브 윗면 중심 픽셀 (화면 표시용)
pose.orientation 영상에서 큐브 면 방향 (z 축 회전, 0~90°)
height_mm, level 탁자에서 윗면까지 높이, 쌓인 층 (0 = 모름)
grasp_u, grasp_v 집기용 픽셀: 2층 이상이면 1층 높이로 원근 보정한 픽셀 (0, 0 = 채우지 않음)

3.1 층 (깊이)

  1. 큐브 둘레 고리(큐브 반쪽 폭의 2~5 배)의 깊이를 3D 점으로 바꿔 탁자 평면을 RANSAC 으로 맞춘다 (판 구멍·옆 큐브·옆면은 평면에서 먼 점이라 빠진다).

  2. 윗면 = 큐브 중심 원(0.8 r) 깊이 중 카메라에 가까운 쪽 25 % 지점.

  3. 높이 = 윗면 점에서 탁자 평면까지 수직 거리. 층 = round(높이 / 40 mm).

카메라가 비스듬해서 같은 픽셀의 깊이 차이로 재면 2층이 88 mm 로 나왔다 - 그래서 평면까지 수직 거리로 잰다. 실측: 1층 37~42 mm, 2층 78~80 mm.

깜빡임 수정: 평면 맞추기 마지막의 np.linalg.svd 가 점 약 5000 개에 5000 x 5000 행렬까지 만들어 큐브 하나에 170 ms 가 걸렸다. 4 개면 한 장 0.7 초 -> 깊이가 밀려 다음 장이 「층 모름」 -> 「· 2층」 글자가 깜빡였다. full_matrices=False 로 큐브당 3.5 ms, 발행 3 Hz -> 13.4 Hz, 「층 모름」 장 0 %.

3.2 쌓인 큐브 원근 보정 (grasp_u/v)

카메라 보정은 1층 큐브 윗면 높이 기준이라, 2층 이상 윗면은 카메라 바로 아래 점에서 바깥쪽으로 밀려 보인다 (카메라 0.8 m, 바로 아래에서 300 mm 떨어진 2층이면 약 16 mm). 윗면 중심 3D 점을 탁자 평면 법선을 따라 1층 윗면 높이로 내린 뒤 다시 투영한 픽셀을 grasp_u/v 에 담는다 (cube_top_measure). 브리지는 이 픽셀로 로봇 좌표를 계산한다.

3.3 큐브 각도

윤곽의 cv2.minAreaRect 각도를 90° 대칭으로 접어 pose.orientation 에 담는다. 작은 큐브는 장마다 2~4° 흔들린다.

4. 브리지 집기 보정 (aris3_real_bridge)

기능 하는 일 끄기
그리퍼 각도 맞추기 큐브 위 접근 높이에서 J6 만 돌려 그리퍼 면을 큐브 면에 맞춘 뒤 집는다. 놓을 때는 큐브 면이 팔 방향(베이스 -> 놓을 자리)과 평행·수직, 쌓을 때는 받침 큐브와 같은 각도. 90° 대칭이라 최대 45°, 한 번 10° 씩 (RobotLink.jog_joint), 2° 미만이면 돌리지 않음 align_yaw:=false
쌓인 큐브 집기 층만큼 집는 높이를 올리고 (level_lift), 위치는 grasp_u/v 로. 4층 넘게 재지면 거부 -
큐브 중심 맞추기 각도를 맞춘 뒤 접근 높이에서 새 검출 3 장의 중앙값으로 큐브 중심을 다시 재서 그 바로 위로 옮긴 다음 하강. 1.5 mm 미만이면 그대로, 25 mm 넘으면 큐브가 움직인 것으로 보고 멈춤. 넓이가 30 % 넘게 다른 장(그리퍼에 일부 가려짐)은 버리고, 못 재면 처음 좌표로 center_grasp:=false
그리퍼 열면 「빈손」 그리퍼 열기(버튼·음성)가 끝나면 잡음 상태를 지운다 -

집기 순서: 접근 높이로 -> (각도 맞추기) -> (중심 맞추기) -> 열기 -> 하강 -> 닫기 -> 잡았는지 확인 -> 들기. 각도 계산: Doosan TCP 자세 [A, B, C] (ZYZ 오일러) 로 툴 X 축의 베이스 방향을 구하고, 툴 Z 축이 아래(·z ≈ -1)면 J6 를 d 돌릴 때 그리퍼 yaw 는 -d 돈다. 손목이 180° 넘게 감기면 90° 다른 같은 모양 쪽을 고른다. 전제: 그리퍼 중심이 J6 축 위 (손목을 돌려도 손끝 XY 가 그대로).

5. 카메라 보정: 탁자 블록 마커

보정 기준은 「1층 큐브 윗면 중심 픽셀 -> 그 큐브를 집는 TCP」 호모그래피 (PixelCalibration, 4 점 이상). 블록 윗면에 ArUco 마커(DICT_4X4_50, ID 0, 파라미터 marker_id)를 천장을 보게 붙여 쓴다.

5.1 블록 자동 기록 (권장 - 사람은 블록 자리만 옮김)

ARIS 「블록 자동 기록 (로봇이 잡아서)」 (RealCalibration AUTO_RECORD):

  1. 마커 중심·각도를 재서 지금 보정으로 블록 위치 계산 (오차 몇 mm - 손가락이 약 106 mm 벌어져 충분).

  2. 블록 위 -> 손목을 블록 각도에 맞춤 -> 열기 -> 하강 -> 닫기(한 축 가운데) -> 열기 -> 올려 손목 90° -> 하강 -> 닫기(다른 축도 가운데) -> 잡았는지 확인 -> 그때 TCP = 블록 중심 기록 -> 열기 -> 올리기 -> 홈.

  3. 홈에서 마커를 다시 재서 (가운데 맞추며 블록이 밀렸을 수 있음) 자동 보정점 하나.

  4. 블록 자리를 바꿔 6~8 번 -> 「보정 저장」 = 자동 보정점으로 새 보정 (예전 파일은 real_camera_calib.json.bak-시각).

자동 보정점은 지금 보정과 따로 모은다 (지금 보정은 블록을 찾아가는 데 씀). 「마지막 점 삭제」 는 자동 보정점부터. 시작하지 않는 경우: 그리퍼가 무언가를 잡고 있음, 마커가 안 보임, 블록이 도달 범위(150~750 mm) 밖. 두 번째로 닫아도 빈손이면 기록하지 않고 멈춘다.

5.2 손으로 기록 (예전 방식, 마커로 정확해짐)

「① 마커·큐브 픽셀 기억」 -> 조그·손으로 움직이기로 그리퍼를 블록을 집는 자세로 -> 「② 로봇 위치 기록」. ①은 마커가 보이면 마커 중심(대각선 교점, 실측 흔들림 0.24 px ≈ 0.3 mm), 없으면 화면에서 고른 큐브(60 px 안).

5.3 블록 높이·3D 일관성

  • 마커 둘레 탁자 평면까지 깊이로 블록 높이를 잰다 (실측 39.8 mm). 큐브(40 mm)와 5 mm 넘게 다르면 픽셀은 큐브 높이 윗면 중심으로, 집는 높이 Z 는 TCP z - (블록 - 40 mm) 로 고쳐 기록한다.

  • 마커 3D 점(cam)이 있는 점이 4 개 이상이면 강체 변환 하나로 맞춘 잔차를 보정 요약에 「마커 3D 일관성 최대 … mm」 로 보인다. 한 점만 크면 그 점을 잘못 기록한 것.

코드: aris3_real_bridge/aris3_real_bridge/marker_calib.py (마커 찾기·각도·깊이·평면·일관성), bridge_node.py (_measure_marker, _auto_start), real_pick.py (block_calibration_point).

6. 음성: 「그리퍼 열어」

「아리스, 그리퍼 열어 / 손 펴 / 집게 벌려」 -> 팔은 그대로 그리퍼만 연다 (대답 「네, 그리퍼를 엽니다.」). 그리퍼·손·집게 + 열/펴/벌 이 함께 있어야 한다 (「문 열어」·「열어」 만은 아님 - 잡담으로 큐브를 떨어뜨리지 않게). 낱말 표(command_parser.py)와 Claude Haiku 해석기(llm_parser.py) 모두 gripper_open. 조작 허용은 음성으로 켜지지 않는다.

7. ARIS 화면

  • 카메라 라벨: red_cube_2 · 2층 · 42° 0.93 (이름 · 층 · 각도 · 신뢰도).
  • 실물 집기 패널: 「① 마커·큐브 픽셀 기억」, 「② 로봇 위치 기록」, 「마지막 점 삭제」, 「보정 저장」, 「블록 자동 기록 (로봇이 잡아서)」.
  • 그리퍼 패널 「잡은 상태」: 큐브 잡음 / 빈손 / 모름 (실물은 브리지 판단, 시뮬레이션은 닫힌 정도).

8. 인터페이스 변경 (cross-package 계약)

인터페이스 변경
msg/DetectedObject height_mm, level (11-13), grasp_u, grasp_v (11-14). pose.orientation 에 픽셀 검출의 회전각
srv/RealCalibration REMEMBER 가 블록 마커 우선, AUTO_RECORD=6 추가
action/RealPickPlace 변경 없음 (각도·중심은 브리지가 검출에서 읽음)

인터페이스를 바꾸면 쓰는 패키지를 모두 다시 빌드하고 노드를 껐다 켠다. ARIS 가 켜진 채로 인터페이스를 다시 빌드하지 않는다 (실행 중인 노드가 쓰는 라이브러리를 덮어씀).

10. 실물에서 확인한 것 / 아직인 것

확인 (2026-11-14):

  • 각도 맞추기: 큐브 39° 에 J6 -38.9° (4 번에 나눠) 돌려 잡기 성공. 중심 맞추기 「이미 중심 위」.
  • D455 마커 측정: 96 장 모두 검출, 중심 흔들림 0.24 px, 블록 높이 39.8 mm.

아직:

  • 블록 자동 기록 실물 실행 (블록이 판 구멍·모서리에 걸리지 않고 미끄러지는지).
  • 쌓인 큐브 원근 보정의 실물 정확도, 중심 맞추기가 실물에서 그리퍼에 가려지는 정도.
  • 그리퍼 중심이 J6 축 위라는 가정.
