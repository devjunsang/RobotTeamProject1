ARIS3 학습 가이드

코드는 같이 만들었지만, 왜 그렇게 짰는지는 직접 이해해야 실물 앞에서 판단할 수 있습니다. 이 문서는 모듈 사이의 통신 흐름, 실물 경로가 동작하는 순서, 안전장치, 실제로 겪은 버그, 직접 해 볼 과제를 모았습니다.

학습 순서전체 통신 흐름도인터페이스 표 집어서 옮기기 순서GUI 스레드 구조안전장치 층 버그 사례집직접 해 볼 과제코드 읽기 순서

학습 순서

  1. 그림부터: 아래 「전체 통신 흐름도」 에서 모듈 이름과 화살표 종류(토픽·서비스·액션)를 손으로 따라가 봅니다.
  2. 직접 보기: 시뮬레이션을 띄우고 ros2 topic list, ros2 action list, ros2 service list 로 그림의 이름이 실제로 있는지 확인합니다.
  3. 한 동작 따라가기: 「집어서 옮기기 순서」 그림을 보며 ros2 topic echo /aris3/real/state 로 상태가 바뀌는 것을 봅니다.
  4. 버그 사례 읽기: 각 사례의 「확인 방법」 명령을 직접 쳐 봅니다. 교재에 없는 현장 감각은 여기서 생깁니다.
  5. 과제 하나: 쉬운 과제부터 직접 구현하고, 테스트가 통과하면 리뷰를 받습니다.

전체 통신 흐름도

모든 모듈은 ROS 2 공용 인터페이스(aris3_interfaces)로만 이야기합니다. GUI 는 로봇에 직접 붙지 않습니다. 같은 GUI 가 시뮬레이션에서는 위쪽(초록 띠) 경로를, 실물에서는 아래쪽(붉은 띠) 경로를 씁니다.

토픽 (계속 흘려보냄)서비스 (묻고 바로 답)액션 (오래 걸림 · 진행 · 취소)

굵은 붉은 선 = 액션, 금색 점선 = 서비스, 시안 선 = 토픽. 모든 노드의 로그는 /rosout 으로 GUI 로그 창에 모입니다 (그림에서는 생략).

「집어서 옮기기」 한 번의 순서 (실물 경로)

사람이 「아리스, 이거 저기로 옮겨줘」 라고 말한 뒤 로봇이 움직이기까지 누가 무엇을 하는지입니다. 세로선이 각 모듈, 화살표가 메시지입니다.

GUI 스레드 구조 — 왜 화면이 멈추지 않는가

ROS 콜백과 화면 그리기는 다른 스레드에서 돕니다. ROS 쪽은 받은 값을 잠금(mutex) 아래 보관만 하고, 화면은 100 ms 마다 그 복사본(snapshot)을 읽습니다. 그래서 카메라 영상이 빨리 들어와도 버튼이 굳지 않고, 화면이 바빠도 ROS 메시지를 놓치지 않습니다.

안전장치 층

하나가 뚫려도 다음 층이 막도록 겹쳐 두었습니다. 위에서부터 사람에 가까운 층입니다. 화면의 정지는 인증된 비상정지 장치를 대신하지 않습니다.

버그 사례집

이번 개발에서 실제로 겪은 문제입니다. 「확인 방법」 은 지금도 직접 해 볼 수 있습니다. 공통 교훈은 하나입니다: 추측하지 말고 기록(로그)과 측정으로 원인을 확정한다.

사례 1. 시뮬레이션 팔이 꼼짝도 하지 않음

증상
작업 첫 이동에서 CONTROL_FAILED, 「State tolerances failed for joint 2」. 관절 값이 0 에서 전혀 안 바뀜.
처음 의심
제어기가 켜지기 전에 작업을 보냈다 → 고쳤지만 그대로 실패 (의심이 틀림).
확인 방법
ros2 action send_goal .../follow_joint_trajectory 로 직접 보내기 → 다른 제어기로 바꿔도 안 움직임 → 큐브 detach 를 손으로 보내자 바로 성공.
진짜 원인
파지 보조(DetachableJoint)는 시작할 때 큐브를 손에 붙여 둔다. 떼는 명령을 시작 직후 3초만 보냈는데 받는 쪽(Gazebo 브리지)이 아직 없어서 모두 사라짐 → 팔이 탁자 위 큐브에 묶임.
배울 점
ROS 토픽은 받는 쪽이 없으면 그냥 사라진다. 시작 순서에 기대지 말고 get_subscription_count() 로 받는 쪽을 확인하거나 상태로 결과를 확인한다.

사례 2. GUI 를 껐는데 로봇 접속이 남음

증상
GUI 종료 후에도 dsr_bringup2 가 살아 있음 (실물이면 서보가 켜진 채).
확인 방법
브리지 기록의 KeyboardInterrupt 위치 확인 → 접속 끊기 도중이었음.
진짜 원인
GUI 가 프로세스 그룹 전체에 SIGINT 를 보내면 ros2 launch 도 한 번 더 넘겨줘서 노드가 SIGINT 를 두 번 받음. 두 번째가 정리 코드를 끊음.
수정
정리를 시작하면 SIGINT 를 무시 (signal.signal(SIGINT, SIG_IGN)), 로봇 접속 끊기를 가장 먼저.
배울 점
종료 경로도 기능이다. 「정상 동작」 만 시험하지 말고 끌 때 무엇이 남는지 ps 로 확인한다.

사례 3. 잠금 안에서 로그 — 화면이 굳을 뻔함

증상
(코드를 쓰다가 발견) 관절 조그 함수가 잠금을 잡은 채 log() 를 부름. log() 도 같은 잠금을 잡음.
원인
같은 스레드가 이미 가진 잠금을 다시 기다림 → 영원히 기다림 (교착). std::mutex 는 재진입이 안 된다.
수정
잠금 안에서는 값만 읽고, 잠금을 푼 뒤 로그.
배울 점
잠금 범위는 짧게, 잠금 안에서 남의 함수를 부르지 않는다.

사례 4. pkill -f 가 자기 자신을 죽임 / 느슨한 검색

증상
정리 스크립트가 이상한 종료 코드로 끝남. GUI 가 「브리지가 이미 실행 중」 이라며 띄우지 않음.
원인
pgrep -f 'real_bridge' 는 그 글자가 들어간 모든 명령줄(검색하는 셸 자신 포함)에 걸린다.
수정
실제 노드 프로세스 형태만 찾는 정규식: ^\S*python[0-9.]* \S*/lib/aris3_real_bridge/real_bridge( |$)
배울 점
프로세스는 PID 로 관리하고(setsid 로 띄워 그룹째 끄기), 이름 검색은 최대한 좁힌다.

사례 5. 집기 동작 중 브리지가 5초씩 응답하지 않음

증상
집기 순서 중 정지 명령이 4.6초 늦게 도착, 그리퍼 서비스 응답이 사라짐.
확인 방법
GUI 없이 재현: 0.2초마다 가벼운 서비스를 불러 응답 시간을 잼 → 5초 이상 멈춤 확인. faulthandler 로 멈춘 순간 모든 스레드의 스택을 찍음 (kill -USR1 <pid>).
단서
일하는 스레드는 대부분 쉬고 있고, 주 스레드는 rclpy 실행기가 기다릴 대상 목록(node.clients, node.guards)을 만드는 중. 브리지가 아무 일 안 할 때도 CPU 50 %, 집기 중 90 %. 관절 상태가 100 Hz 로 두 개 들어옴.
진짜 원인
rclpy MultiThreadedExecutor 는 메시지가 하나 올 때마다 노드의 모든 구독·서비스·액션·타이머로 기다릴 목록을 다시 만든다. 100 Hz 관절 상태(그리퍼 각도용)가 이걸 초당 100 번 시켰고, 파이썬은 한 번에 한 스레드만 돌 수 있어(GIL) ARIS·Gazebo 까지 바쁠 때 다른 스레드(정지 서비스, 그리퍼 응답 처리)가 수 초씩 밀렸다.
수정
빠른 토픽은 전용 작은 노드 + SingleThreadedExecutor 로 따로 받는다. 메인 실행기 스레드 8 → 4. 측정: 최대 응답 5 초 이상 → 0.3 초.
배울 점
멈춤 문제는 「멈춘 순간」 의 증거(스택·시간 측정)가 있어야 풀린다. Python ROS 의 실행기·콜백 그룹·GIL 은 C++ 과 다르게 동작한다.

직접 해 볼 과제

각 과제는 「고칠 곳」 과 「확인 명령」 이 있습니다. 테스트가 통과하면 리뷰를 요청하세요. 막히면 어디까지 했는지 알려 주면 그 지점부터 같이 봅니다.

쉬움호출어 오인식 표현 추가

실제로 마이크에 「아리스」 라고 말했을 때 Whisper 가 적은 다른 표현을 받게 합니다.
고칠 곳: aris3_voice/aris3_voice/listening.py 의 WAKE_WORDS, 시험: test/test_listening.py 에 경우 추가
확인: python3 -m pytest -q aris3_voice/test

중간음성 「아리스 멈춰」 = 정지

파서에 stop 동작을 추가하고 GUI 가 받으면 정지를 보냅니다. 정지는 확인창 없이 바로여야 합니다 (왜 그런지 생각해 보기).
고칠 곳: command_parser.py, VoiceCommand.msg 설명, PyQt panels/voice.py, ARIS main_window.cpp
확인: 파서 테스트 + ros2 topic pub --once -w 1 /aris3/voice/text std_msgs/msg/String "{data: '아리스 멈춰'}"

중간ARIS 에 속도 단계 버튼 (느림·보통·빠름)

속도 슬라이더 옆에 버튼 3개를 두어 30·60·100 % 로 맞춥니다. Qt 시그널·슬롯 연습.
고칠 곳: aris3_gui_cpp/src/main_window.cpp 의 buildJogPanel()
확인: colcon build --packages-select aris3_gui_cpp 후 화면에서 눌러 보기

어려움Task Manager 의 집기·놓기 분리

지금은 집기 명령이 놓기까지 한 번에 합니다. 「집기만」·「놓기만」 작업을 추가합니다. 액션 정의 변경 → 모든 사용처 갱신 (AGENTS.md 규칙).
고칠 곳: ExecuteTask.action, task_manager_node.cpp, 두 GUI
확인: colcon test --packages-select aris3_task_manager + 시뮬레이션에서 send_task
